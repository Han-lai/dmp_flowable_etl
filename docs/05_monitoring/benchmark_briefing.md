# ClickHouse 效能壓測結果說明

## 壓測目的

在上線前確認 ClickHouse 資料倉儲能否撐住真實的使用負載。

## 測試條件

- **測試對象**：DG3/SMT/ST02、WJ2/NBU/E5 兩條產線
- **測試方式**：模擬 10 個使用者同時查詢報表，每個人隨機查 12/25 到 12/31 之間的不同日期，共執行 100 筆查詢
- **測試環境**：ClickHouse 容器內部，使用官方壓測工具 `clickhouse-benchmark`
- **SQL 結構**：
  - **Pivot SQL**：與 Superset 報表實際使用的查詢格式相同，包含 6 個 UNION ALL 行列轉置
  - **Standard SQL**：相同篩選條件與聚合邏輯，不含 Pivot 行列轉置

## 壓測結果

### Pivot SQL（報表實際查詢格式）

| 指標 | DG3/SMT/ST02 | WJ2/NBU/E5 |
| :--- | :--- | :--- |
| QPS（每秒完成查詢數） | 10.5 筆/秒 | 12.4 筆/秒 |
| 查詢延遲中位數 (P50) | 0.88 秒 | 0.74 秒 |
| RPS（每秒讀取列數） | 609 萬列/秒 | 716 萬列/秒 |
| 讀取吞吐量 (MiB/s) | 390 MiB/秒 | 459 MiB/秒 |
| 結果回傳速率 (Result RPS) | 695 列/秒 | 817 列/秒 |

### Standard SQL（純聚合，不含 Pivot）

| 指標 | DG3/SMT/ST02 | WJ2/NBU/E5 |
| :--- | :--- | :--- |
| QPS（每秒完成查詢數） | 62.2 筆/秒 | 51.4 筆/秒 |
| 查詢延遲中位數 (P50) | 0.14 秒 | 0.17 秒 |

### 共通指標

| 指標 | 實測值 |
| :--- | :--- |
| 單筆查詢記憶體峰值 | 404 MiB |
| 單筆查詢平均記憶體 | 241 MiB |
| 單筆查詢平均 CPU 時間 | 258 ms |
| 資料壓縮比 | 6.6 倍（4.7 GB → 730 MB） |
| 資料正確性 | 兩組產線各 4 欄位全數吻合 |

## 指標定義（ClickHouse 官方）

| 指標 | 定義 |
| :--- | :--- |
| **QPS** (Queries Per Second) | 每秒**執行完成**的查詢數 |
| **RPS** (Rows Per Second) | 每秒**讀取（掃描）**的資料列數 |
| **MiB/s** | 每秒**讀取**的資料量 |
| **Result RPS** | 每秒放入**查詢結果**的列數（回傳給使用者的部分） |
| **P50** | 所有查詢依延遲排序後的中位數（50% 的查詢比此值快） |

## SQL 結構對效能的影響

相同的資料與篩選條件下，Standard SQL 的延遲中位數為 0.14~0.17 秒，Pivot SQL 為 0.74~0.88 秒。Pivot SQL 多出的時間是其 6 個 UNION ALL 結構導致 ClickHouse 重複讀取同一份資料 6 次所造成。ClickHouse 引擎本身的聚合效能良好，Standard SQL 在 10 人同時查詢下仍可維持每秒 50 筆以上的處理速度。
