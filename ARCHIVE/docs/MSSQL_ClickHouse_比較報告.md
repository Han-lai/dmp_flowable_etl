## 一、比較背景說明

本次評估針對 **同一批 MSSQL 原始資料**，比較兩種不同匯入 ClickHouse 的方案：

| 方案 | 說明 |
|------|------|
| **JDBC Bridge** | 直接以 JDBC query 將資料寫入 ClickHouse，結構貼近 MSSQL 原始 schema |
| **Airbyte** | 透過 Airbyte 同步 MSSQL 至 ClickHouse，內建增量同步、UI 管理與 metadata 欄位 |

## 三、Airbyte 額外欄位說明

Airbyte 於每張表中自動新增以下 metadata 欄位：

| 欄位名稱 | 用途 |
|----------|------|
| `_airbyte_raw_id` | 每筆資料的唯一識別碼，用於追蹤與除錯 |
| `_airbyte_extracted_at` | 資料擷取時間，可作為增量同步 watermark |
| `_airbyte_meta` | 同步過程的 metadata（錯誤訊息、狀態等） |
| `_airbyte_generation_id` | 同步批次識別碼，用於增量與版本控管 |

## 六、重點結論

1. **效能表現**：JDBC Bridge 同步速度約為 Airbyte 的 **7.7 倍**
2. **儲存成本**：JDBC Bridge 約節省 **30%** 儲存空間
3. **功能完整度**：Airbyte 提供完整的 UI、增量同步與資料追蹤能力
4. **資料正確性**：兩種方案在資料筆數上已驗證一致

---

## 七、最終架構建議

### ✅ 建議採用「混合式方案」

| 表類型 | 建議方案 | 理由 |
|--------|----------|------|
| 大表（歷史表、成長快速表） | Airbyte + 增量同步 | 降低每日同步時間與來源系統負擔 |
| 小表或需頻繁全量刷新表 | JDBC Bridge | 追求同步速度與儲存效率 |

---

## 📌 決策總結一句話

> **JDBC Bridge 提供極致效能與低成本，Airbyte 則提供穩定維運與增量能力，建議依表特性採用混合式匯入策略。**
